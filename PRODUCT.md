# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Forge is a personal operating system for Christian Foster: a developer, builder, early adopter, and long-term thinker managing work, personal projects, family, health, life administration, and learning.

## Product Purpose

Forge turns the user’s projects, work, calendar, meetings, ideas, communication, and time into one calm mission-control workspace. Success means the user always sees the next useful direction without rebuilding a system by hand.

## Positioning

Forge is an AI-assisted personal developer operating system: it connects project context, task execution, calendar planning, evidence of time spent, and an adaptive personal assistant in one private workspace.

## Operating Context

The product is used daily on desktop and mobile, alongside browser-based development work. It includes projects, work items, meetings, calendar events, reports, a persistent AI chat, rich notes, shareable read-only project views, and browser-context time capture.

## Capabilities and Constraints

Forge uses React, Vite, TypeScript, Supabase Auth and PostgreSQL with Row Level Security. User data is private by default. Project-specific workflows may define custom data fields, starting with Admired time logs. Chrome extension installation is unpacked/developer-mode until a store release is prepared.

## Brand Commitments

The product is named Forge. It should feel like a capable, thoughtful JARVIS-style assistant: concise, direct, intelligent, supportive without nagging, and optimized for sustained productivity and well-being. Dark, low-glare visuals are intentional.

## Evidence on Hand

The existing Forge application, Supabase schema, and `C:/Users/Admin/Downloads/Timelogs.xls` provide real product and time-log requirements. No external productivity claims, integrations, or AI capabilities should be fabricated.

## Product Principles

- Show the next meaningful action, not an overwhelming system.
- Automate coordination while keeping the user in control of consequential changes.
- Keep real work, time, and decisions connected to their project context.
- Prefer adaptable structures over fixed team-process templates.
- Make attention and progress visible without turning productivity into guilt.
